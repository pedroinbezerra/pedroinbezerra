## 🧭 Constitution-first AI development

One of the most important practices I've adopted is defining a **Project Constitution** before allowing agents to freely evolve a codebase.

The Constitution acts as the highest-level engineering and product reference for the project.

It can define:

* Architectural principles
* Product principles
* Business invariants
* Security boundaries
* Engineering standards
* Evidence requirements
* Decision criteria
* Responsibilities that must remain human
* Rules that agents are not allowed to override

The goal is to prevent an agent from solving an isolated task while accidentally damaging the broader system.

```text
                     Project Constitution
                              │
                              ▼
                 Architecture & Business Rules
                              │
                              ▼
                     Project Context
                              │
                              ▼
                    Specialized Skills
                              │
                              ▼
                         AI Agents
                              │
                              ▼
           Investigate → Plan → Implement → Validate
                              │
                              ▼
                       Human Decision
```

## 🧠 AI engineering practices

| Area                        | How I apply it                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------- |
| **Project Constitutions**   | Persistent principles and constraints that guide agents across the project            |
| **Custom Skills**           | Reusable and project-specific knowledge for recurring engineering tasks               |
| **Context Engineering**     | Structuring what agents need to understand before taking action                       |
| **Repository-aware Agents** | Agents working directly with real codebases, documentation and architecture           |
| **Agentic Workflows**       | Investigation → planning → implementation → testing → validation                      |
| **Business Rule Analysis**  | Using AI to understand and cross-check complex domain behavior                        |
| **Architecture Analysis**   | Evaluating changes against existing boundaries instead of treating tasks in isolation |
| **Code Review**             | AI-assisted analysis of implementation quality, regressions and inconsistencies       |
| **Documentation**           | Keeping technical and product knowledge connected to implementation                   |
| **Model Evaluation**        | Comparing models for coding, reasoning, context handling and tool use                 |
| **Local AI**                | Running and evaluating local models and inference configurations                      |
| **Human-in-the-loop**       | Keeping consequential product and architectural decisions under human control         |
